# AI 연결과 작업 사용법

2026-11-08. UI는 임시 컴포넌트이며 최종 디자인은 오너가 결정한다.

1. 위쪽 `AI 1`에서 연결 설정을 연다. OpenAI·Claude·Gemini 또는 OpenAI 호환/로컬 API를 선택한다.
2. 키는 앱에서 입력한다. 로컬 호환 서버는 키 없이 사용할 수 있다. 외부 연결은 HTTPS, HTTP는 loopback만 허용한다. 모델 목록 조회 후 모델을 선택한다. 목록 조회는 실제 추론 검증과 다르다.
3. 저장을 선택하면 OS 암호화로 보관한다. 지원하지 않는 환경에서는 이번 실행 동안만 사용한다. `다음 AI`는 독립된 AI 1·2·3을 순환한다. 각 AI의 키·대화·모델 연결은 독립적이다.
4. `현재 탭 읽기`는 다음 메시지 한 번에 페이지 내용을 공유한다. `현재 탭 제어 공유`는 네이티브 동의 후 동작 제안을 허용한다. 실제 동작은 다시 승인한다. 탭에서 직접 클릭/입력하거나 탭을 전환하면 공유가 회수된다.
5. 별도 AI 작업 주소를 열면 사람 탭과 쿠키·저장소가 분리된 창이 생긴다. `AI 작업 읽기` 또는 `여러 단계 작업`을 사용한다. 여러 단계 작업은 페이지를 자동 재공유한다는 네이티브 승인 후 최대 10단계로 진행한다. origin 변경·불확실한 결과는 멈추며 확인 후 계속할 수 있다.
6. 모델이 제안한 CLICK/FILL/SELECT/SCROLL/NAVIGATE는 `동작 검토`와 네이티브 확인을 통과해야 실행된다. 비밀번호·파일 입력·민감 필드는 제외한다. WAIT는 최대 5초이고 즉시 취소할 수 있다. HANDOFF·중단은 권한을 회수한다. 이미 서버에 보낸 효과를 되돌리지는 않는다.

## 제공사와 옵션

OpenAI는 `/v1/chat/completions`, Claude는 `/v1/messages`, Gemini는 `/v1beta/models/{model}:generateContent`, 호환 연결은 `/models`와 `/chat/completions`를 사용한다. Ollama 예시는 `http://127.0.0.1:11434/v1`, LM Studio는 `http://127.0.0.1:1234/v1`이다. 로컬 서버와 모델은 별도로 실행해야 한다. 웹 구독과 API 요금은 별개다.

출력 상한은 128~8192 토큰, 기본 2048이다. OpenAI 추론 강도는 해당 모델이 지원해야 한다. 지원하지 않는 옵션은 서버가 거부할 수 있다. 목록은 첫 페이지 최대 300개이며 수동 모델 ID 입력을 지원한다. 응답은 비스트리밍이다.

## 정보·비용·저장

페이지는 표시 텍스트 12,000자와 최대 100개 요소만 공유한다. 입력값·숨김/비공개 내용·iframe·shadow DOM은 제외한다. 화면에 표시된 개인정보를 모두 판별할 수는 없으므로 공유 전 확인한다. 역할·라벨·허용 동작은 페이지 데이터이며 승인 권한이 아니다.

대화는 최근 20개 메시지/45,000자로 제한한다. API 응답은 512 KiB, 요청은 60초, 대화당 30회와 최소 1.5초 간격이다. 대화 보관은 명시적 저장 버튼을 눌렀을 때만 OS 암호화하며 AI별 보관본 하나를 교체한다. 불러오기 자체는 모델 호출이 아니며 다음 전송부터 현재 모델에 포함된다.

토큰은 서버 보고 수치다. 단가·컨텍스트 한도는 사용자가 입력하며 비용/잔여량은 추정이다. 예산 기능은 보수적인 요청 예약 비용을 적용하지만 실제 청구 상한을 보장하지 않는다. 오류·중단 요청은 예약 비용이 남을 수 있다. 실제 계정 잔액을 만들어 표시하지 않는다.

감사 이력은 시간·origin·동작·결과만 보관하며 입력 값·본문·API 키는 기록하지 않는다. 설정과 저장 자료는 현재 OS 프로필에 속하며 Supabase 계정에 업로드하지 않는다.

## 검증과 한계

[구현 검증 기록](BROWSER-AI-IMPLEMENTATION.md)을 참조한다. 실제 production UI/IPC/어댑터/ToastIR/Guard를 로컬 응답 fixture로 검사했다. 유효한 제공사 키와 실제 로컬 모델이 없으므로 실제 추론·모델의 작업 정확도·청구는 미검증이다. Windows OS 암호화 왕복도 별도 검증이 필요하다. 테스트 통과는 모든 프롬프트 인젝션에 대한 안전성 보증이 아니다.
