# 아키텍처와 진행 상태

## 선택

Electron은 Chromium과 Node 기반 애플리케이션 계층, 명시적 프로세스 경계, Windows 배포 생태계를 제공한다. CEF는 브라우저 통합 제어 범위가 넓지만 별도의 네이티브 호스트와 업데이트·패키징 관리 비용이 크다. Chromium 직접 포크는 브라우저 동작에 대한 가장 큰 제어력을 제공하지만 유지보수 및 신속한 보안 패치 부담이 매우 크다. 초기 단계는 Electron을 선택한다. Electron의 Chromium 버전과 보안 지원을 지속적으로 갱신해야 하며 선택 자체가 안전성을 보증하지 않는다.

## 경계

메인 프로세스가 뷰, 탐색과 정책을 소유한다. 애플리케이션 UI는 샌드박스 렌더러이며 제한된 preload 브리지로 명령을 보낸다. 메인은 UI의 최상위 프레임과 발신자를 확인하고, 명령 종류와 인자를 검사한다. 외부 웹 콘텐츠는 preload와 Node 통합이 없는 샌드박스 WebContentsView에서 표시된다. UI는 상태 표시와 입력만 담당하며 보안 결정권이 없다. 탭과 도구 모음은 별도 모듈이며 시각 속성은 CSS 토큰으로 관리한다. 최종 디자인은 프로젝트 오너가 결정한다.

웹 탐색은 HTTP(S)로 제한되고 자격 증명 포함 URL은 거부한다. 권한 요청, 팝업과 다운로드는 현재 기본 거부한다. 사람 탭은 human 파티션을 사용한다. 실험 AI 작업 팩토리는 작업별 메모리 세션을 생성한다. Guard v2와 최소 DOM 수집/실행기 연결은 로컬 Electron 공격 테스트로 확인했고 실제 모델/제품 UI 통합은 아직 없다.

## 단계별 현황

- 1단계 진행 중: TypeScript/Electron 셸, 일부 탭·탐색, 제한적 IPC, 주소 정책 및 단위 테스트. Linux Electron 보안 E2E 검증 완료, Windows 실행 미검증.
- 2~6단계 진행 상태: ToastIR/ToastCore는 요소 매핑과 제한된 동작의 실험 경로를 구현했다. 전체 바이너리 IR와 모델/협업 기능은 미구현. Guard는 이 실험 경로에 연결되어 있으나 모델/제품 UI에는 연결되지 않았다. OS 키 저장 어댑터와 서명 업데이트 검증기는 독립 모듈 상태다. Windows x64 테스트 폴더 패키지와 fuse 검증은 구현했다. 승인 UI, 비용 집계, 벤치마크, Windows 직접 실행, 코드 서명과 자동 업데이트는 아직 없다.
- 방문 기록, 북마크, 검색 설정, 사이트별 권한 UI, 다운로드 관리, 세션 복원 및 기본 브라우저 등록도 미구현.

실행기나 API 키 기능을 구현하기 전까지 UI에 가짜 제어를 제공하지 않는다. 추후 AI 명령은 구조화된 스키마, 사이트/탭 범위와 상태 버전, 별도 권한 승인, 중단 및 감사 기록을 통과해야 한다. 외부 페이지는 데이터이며 지시 권한이 없다. PQ TLS는 Chromium 및 실제 협상 결과를 확인한 후에만 표시한다.

보안 정책과 증거의 현재 기준 문서는 `SECURITY.md` 및 `docs/SECURITY-VALIDATION.md`다. UI는 전용 프로토콜 및 별도 메모리 세션으로 제공하고 웹 콘텐츠 세션과 분리했다. UI 변경으로 메인 프로세스의 권한 결정을 옮기면 안 된다.
