# 공개 검색 서비스 연동 조건 검토

확인일: 2026-11-08 (Asia/Seoul). 공식 웹사이트·API 문서·약관을 직접 조회했다. 이 문서는 공개 문구와 제한된 연결 시험에 대한 기록이며, 제공사의 개별 승인이나 법적 확정 판정을 의미하지 않는다.

## 목표와 범위

ButterToast는 여러 사용자에게 배포할 브라우저이며, 현재 운영 예산은 0원이다. 외부 검색 결과를 ButterToast의 임시 UI에 표시할 수 있는 공식 경로를 찾는다. Google 사용도 허용된 상태다. 최종 디자인 결정권은 프로젝트 오너에게 있다.

공개 웹페이지 열람, 웹페이지 자동 수집, 공식 검색 API 이용, 오픈소스 검색 소프트웨어의 자체 운영은 서로 다른 조건을 갖는다. 소프트웨어의 공개 라이선스를 운영 중인 타인의 서버에 대한 무제한 이용 허가로 해석하지 않았다. 무료 한도는 별도 명시가 없는 한 앱·계정 전체가 공유한다.

## Mojeek: 표시·AI 활용과 수집 경로를 구분

공식 [Search API 약관](https://www.mojeek.com/about/legal/api-terms.html)의 Usage 항목은 다음을 허용한다.

- 인터넷 검색 화면과 RAG, grounding, AI agent/assistant, model evaluation에 API 데이터 이용.
- 검색 결과 순위 변경, 다른 검색엔진 결과와 결합.
- 구독 등 상업적 이용과 제3자 광고 표시. Mojeek 귀속 표시가 필수는 아님.
- 법령과 약관의 예외에 저촉되지 않는 범위의 데이터 변경 및 새 콘텐츠 생성.

동시에 다음 제한이 있다.

- 저장 권리가 없는 플랜은 동일 사용자에게 제공하기 위한 최대 1시간 임시 캐싱만 허용한다. Startup의 공용 장기 캐시를 만들어 비용을 줄이는 구조로 설계하지 않는다.
- 영구 저장은 저장 권리가 포함된 플랜에서만 허용한다. API 데이터를 별도 검색 색인의 일부로 사용하는 것은 금지한다.
- API에 없던 URL·제목·설명을 Mojeek의 원래 결과인 것처럼 표시하지 않는다. 별도로 생성한 AI 답변 자체는 허용된다고 명시한다.
- 링크된 외부 페이지·제3자 콘텐츠에 대한 권리는 별도다.

공식 [가격표](https://www.mojeek.com/services/search/web-search-api/) 기준:

| 플랜 | 가격 (세금 별도) | 요청당 결과 수 | 저장 |
| --- | --- | --- | --- |
| Startup | £2 / 1,000요청 | 최대 10개 | 같은 사용자 대상 최대 1시간 임시 캐시 |
| Business | £3 / 1,000요청 | 최대 40개 | 저장 권리 포함, 별도 색인 구축 금지는 유지 |
| Enterprise | 별도 협의 | 최대 100개 | 약정 조건 확인 |

Startup 가입 후 무료 크레딧 신청이 가능하다고 안내하지만, 조회한 페이지에는 무료 크레딧 액수나 매월 갱신되는 무료 한도가 명시되지 않았다. 계정 개설에는 카드가 필요하다. 자동 결제를 처리하지 않는 PAYG 방식이라는 안내도 확인했다.

예: 사용자가 1,000명이고 하루 각 5회의 API 요청을 하면 30일간 150,000요청이다. Startup 단가를 단순 적용하면 £300이며, 세금·추가 요청·기타 운영 비용은 제외한 계산이다. 가격표의 일일 최대 요청 수는 무료 제공량이 아니다.

일반 [Mojeek 웹사이트 약관](https://www.mojeek.com/about/terms.html) 3항은 허가 없는 scraping을 명시적으로 금지한다. 따라서 무료 검색 페이지를 추출해 위 API의 유료 사용을 대체할 수 있다고 해석하지 않는다.

## Wiby: 공개 API 연결 시험

공식 [JSON API 안내](https://wiby.me/json/)의 이용 조건:

> 1. Use this service at your own risk.
> 2. Provide a link to wiby.me with the results.

[공식 소프트웨어 안내](https://wiby.me/about/guide.html)는 메타검색엔진 연결용 API라는 용도도 설명한다. 해당 페이지의 오픈소스 라이선스와 별개로, 운영 중인 wiby.me의 API 안내에서 실제 이용 경로를 확인했다.

공식 엔드포인트에 키·계정 없이 일반 GET 요청을 각 한 번 실행했다. 검색 결과 페이지를 자동 수집하거나 사용자 검색 기록을 전송하지 않았다.

| 검색어 | HTTP | 응답 | 결과 수 |
| --- | --- | --- | --- |
| `linux` | 200 | JSON 배열 | 11 |
| `한국` | 200 | JSON 배열 | 9 |

응답 필드는 `URL`, `Title`, `Snippet`, `Description`이었다. 이 결과는 연결·형식 확인이며 한국어 품질이나 대규모 서비스 가용성 검증은 아니다. 한국어 요청에서도 여러 언어가 섞인 결과가 관찰되어, 한국어 중심의 일반 검색 품질은 별도 평가해야 한다.

[소개](https://wiby.me/about/)는 개인·학술·단순 웹페이지 발견을 강조한다. [개인정보 정책](https://wiby.me/about/pp.html)은 원시 접근 로그를 최대 48시간 보관한다고 명시한다. 사용자 PC에서 직접 요청해도 검색 제공사에는 요청이 전달된다.

문서에 호출 한도가 없다는 사실을 무제한 제공 약속으로 해석하지 않는다. 대규모 기본 검색으로 채택하기 전에 예상 부하와 운영 조건을 확인할 필요가 있다. 이번 조사에서 운영자에게 연락하지 않았다.

### 추가 검색 범위 확인

2026-11-08에 미리 정한 8개 검색어를 각각 한 번씩 공식 JSON API에 요청했다. 모두 HTTP 200이었고, 추가 페이지·자동 재시도는 요청하지 않았다. 아래 수치는 첫 페이지 응답의 항목 수이며 전체 색인 크기나 총 검색 결과 수가 아니다.

| 검색어 | 첫 페이지 항목 수 | 관찰 |
| --- | --- | --- |
| `서울 날씨` | 0 | 빈 배열 |
| `삼성전자 주가` | 0 | 빈 배열 |
| `강남역 맛집` | 0 | 빈 배열 |
| `파이썬 리스트 정렬` | 0 | 빈 배열 |
| `python list sort` | 12 | 첫 결과는 투자은행의 Python 개발 이야기. 첫 다섯 결과의 제목·설명에는 비교 언어 참고서, Lisp 사용자를 위한 Python 등도 포함 |
| `linux` | 11 | Linux 관련 문서·프로그램·개인 사이트·오래된 커널 디렉터리 등이 섞임 |
| `HTML tutorial` | 12 | HTML 입문 문서와 Ada95 튜토리얼 등이 섞임 |
| `Amiga` | 12 | 고전 게임, Amiga 커뮤니티·에뮬레이터 등 주제에 맞는 결과 관찰 |

[공식 등록 기준](https://wiby.me/submit/)은 단순한 HTML과 비상업 사이트를 선호하고, 외관을 위한 과도한 스크립트·CSS 및 방해성 광고를 피하도록 안내한다. 대부분 제출한 페이지 하나만 수집한다고도 명시한다. 따라서 등록된 사이트의 모든 페이지를 수집한다고 가정할 수 없다. 확인한 공식 자료에는 현재 전체 색인 크기가 제시되지 않아 다른 엔진 대비 비율을 산출하지 않았다.

이는 작은 표본이며 전체 품질 평가가 아니다. 다만 한국어 일상 검색을 핵심 용도로 하는 ButterToast의 기본 엔진으로 채택할 근거는 부족하다. Wiby를 연동 조건 검증·개인 웹/고전 컴퓨터 관련 보조 검색 후보로 유지하고, 일반 검색 공급원과 구분하는 것이 적절하다.

## Marginalia: 비상업용 라이선스와 공유 한도

[공식 API 문서](https://about.marginalia-search.com/article/api/)에서 무료 비상업용 키를 신청할 수 있으며, 데이터는 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/)으로 제공된다. 출처·라이선스 표시, 변경 사실 표시, 비상업 목적, 해당되는 공유조건 준수가 필요하다. 이 데이터 라이선스를 ButterToast 소프트웨어 전체의 라이선스와 자동으로 동일시하지 않는다.

통합 개발용 공개 키 `public`으로 `linux` 검색을 한 번 요청한 결과 HTTP 429를 받았다. 재시도나 한도 우회를 하지 않았다. 공개 키는 여러 사용자가 공유하며 제한에 자주 걸릴 수 있다는 공식 안내와 일치한다. 제품 배포용 무제한 공용 키로 취급할 수 없다.

일반 검색 웹페이지의 robots.txt는 `/search` 등을 금지한다. 이번 검토의 허용 근거는 일반 페이지가 아니라 공식 API와 그 라이선스다.

## 국내 API: 무료 한도와 최신 약관을 함께 확인

### NAVER

기존 [웹문서 검색 문서](https://developers.naver.com/docs/serviceapi/search/web/web.md)의 하루 25,000회 안내만으로 새 프로젝트에 등록 가능하다고 판단하면 안 된다. [2026-10-07 개정 약관](https://developers.naver.com/products/terms/)의 부칙은 기존 개발자센터 검색 API 신규 접수를 2026-07-30 24:00 종료하고 기존 고객의 전환 유예기간을 2027-06-30 24:00까지로 안내한다.

후속 확인에서 신규 경로인 [NAVER API HUB](https://www.ncloud.com/product/applicationService/naverApiHub)를 찾았다. 상품 요금표는 검색 API 0~775,000건 구간을 0원, 일 최대 25,000건으로 표시한다. 따라서 네이버 검색 API 전체가 종료됐다고 해석해서는 안 된다. 가입·승인 가능 여부나 실제 인증 호출은 이번에 시험하지 않았다.

동일 상품 페이지에 링크된 공식 PDF 「NAVER API HUB 서비스 이용 약관」도 내려받아 검토했다. 검색 API 특약 1.1~1.4는 다음을 명시한다.

- 네이버 검색 결과임을 표시하고 원본 출처·링크를 제공.
- 데이터를 독립적으로 가공 없이 노출. 결과 순위·내용 변경 및 결과 사이에 다른 내용 삽입 금지.
- 데이터를 AI에 입력하거나 학습·개선·평가·노출 등에 활용하는 행위 금지.
- 검색 결과 페이지 광고 및 검색 API를 활용한 수익 창출 금지.
- 기기 임시 보관은 규정된 목적에서 24시간 또는 새 질의 시점 중 빠른 때까지. 서버 이력 조회 등은 별도 목적·기간 조건 적용.

따라서 원문 순위와 내용을 보존하는 일반 검색 표시와, AI 입력·요약·혼합 검색을 구분해야 한다. 단순 UI 배치 변경의 상세 범위와 BI 가이드 준수도 구현 전에 확인해야 한다. API HUB가 기존 API의 AI 제한을 없앴다고 보지 않는다.

### Kakao Daum

[기능 안내](https://developers.kakao.com/docs/ko/daum-search/common), [REST API 문서](https://developers.kakao.com/docs/ko/daum-search/dev-guide), [쿼터](https://developers.kakao.com/docs/ko/getting-started/quota)를 확인했다. 무료 쿼터는 웹문서 검색 일 30,000건, Daum 검색 전체 일 50,000건, 전체 API 월 3,000,000건이며 앱 사용량을 합산한다.

[서비스 약관](https://developers.kakao.com/terms/ko/site-terms) 제11조 ③ 및 [운영정책](https://developers.kakao.com/terms/ko/site-policies)은 사전 승낙 없는 정보 복사·변경·검색엔진 입력·타인 제공 등에 폭넓은 제한을 둔다. 공식 검색 API를 통한 통상적인 결과 표시 경로는 제공되지만, 임의 재정렬·AI 전달·별도 검색 서비스로 재제공까지 포괄 허용된다고 확정하지 않았다. 인증 키가 없어 실제 검색 호출은 시험하지 않았다.

## Brave 추가 확인

2026-11-08에 [API 제품 설명](https://brave.com/search/api/), [공식 요금표](https://api-dashboard.search.brave.com/documentation/pricing), [API 약관](https://api-dashboard.search.brave.com/terms-of-service), [검색 도움말](https://search.brave.com/help)에서 연결한 [일반 이용약관](https://brave.com/terms-of-use/)을 확인했다.

- Brave는 자체 색인을 사용하는 범용 검색 서비스이며 웹·뉴스·이미지·동영상 등의 결과를 제공한다. Wiby의 단순·비상업 페이지 선호와는 수집 방향이 다르다. 홍보 문구의 웹 커버리지 비율을 독립 검증된 측정값으로 사용하지 않았다.
- Search API는 현재 $5/1,000요청이며 매월 무료 $5 크레딧이 적용된다. 같은 단가의 Search 요청만 쓰면 약 1,000요청에 해당한다. 계정 전체가 공유하는 한도다. 사이트 첫머리의 '최대 $20 무료' 문구는 여러 제품의 크레딧을 합친 안내이므로 Search에 $20가 모두 적용된다고 계산하지 않는다.
- FAQ는 카드 등록이 필요하고 선불 크레딧 구매 방식이라고 안내한다. 무료 크레딧 이후의 계속된 API 이용을 무료라고 표현하지 않는다.
- API 약관은 Customer Applications와의 API 통합 및 결과 이용 라이선스를 제공한다. 동시에 작동에 필요한 일시 저장을 제외한 결과 저장·DB 구축, 파생물, 재판매·재배포, 모델 학습·평가 등에는 제한을 둔다. 제품은 LLM Context 등 AI 검색 기능을 제공하므로 일반적인 검색 문맥 제공과 모델 학습 권한을 혼동하지 않는다. 구체적인 결과 변형·요약·보관 설계에는 해당 플랜의 문서·계약 범위를 적용해야 한다.
- 일반 이용약관에서 과도한 부하, 서비스 방해, 접근 제한 우회 금지를 확인했다. 무료 검색 결과 페이지를 자동 추출해 별도 서비스로 재구성하도록 명시적으로 허용하는 문구는 확인하지 못했다. 그 사실만으로 모든 로컬 보기 변경이 금지됐다고 확정하지는 않는다.
- 유효한 API 키가 없어 실제 검색 API 응답·한국어 품질을 시험하지 않았다. 일반 검색 페이지 수집으로 인증된 API 시험을 대체하지 않았다.

검색 범위 면에서는 일반 검색 공급원 후보지만, 여러 사용자에게 자체 검색 화면을 무제한 무료 제공할 비용 문제가 해결된 것은 아니다. Brave 사이트를 정상적으로 여는 기본 검색과 공용 API를 사용하는 자체 결과 화면은 별도로 판단한다.

## 그 밖의 확인 자료

- [Mwmbl 약관](https://mwmbl.org/terms): 데이터의 비상업 라이선스와 scraping·과도한 자동 질의 제한을 함께 읽어야 한다.
- [DuckDuckGo 약관](https://duckduckgo.com/terms), [허용 사용 정책](https://duckduckgo.com/acceptable-use): 확인한 범위에서 전체 결과 재구성의 명시적 허용 근거를 확보하지 못했다. 금지 조항을 발견하지 못했다는 사실을 허가로 취급하지 않았다.
- [SearXNG 검색 API](https://docs.searxng.org/dev/search_api.html): 공개 인스턴스의 JSON 등 형식 비활성화 가능성과 상위 검색 서비스로 질의를 전달하는 구조를 명시한다.
- [YaCy](https://yacy.net/): 자체 운영 가능한 검색 소프트웨어/P2P 대안으로만 확인했다.
- [searchmysite.net API 문서](https://searchmysite.net/pages/documentation/#api), [약관](https://searchmysite.net/pages/terms/): 도메인 지정 API와 과도한 사용 제한. 현재 공개 웹 전체용 API라고 추천하지 않는다.
- [Brave API 약관](https://api-dashboard.search.brave.com/terms-of-service): 앱 연동 라이선스와 저장·파생물·재배포 등 제한. 사이트의 일반 결과 HTML 수집 허가로 확대 해석하지 않는다.
- 예전 자료에 오픈 검색엔진으로 등장하는 Stract의 현재 [소개](https://stract.com/about)는 미디어 연락처·마케팅 제품을 설명한다. 오래된 소개만으로 현재 무료 웹 검색 API 후보로 제시하지 않았다.

## 구현을 결정할 때의 조건

1. Wiby를 먼저 시험한다면 `검색 입력 → 공식 JSON API → 텍스트·검증된 링크로 자체 UI 표시` 경로를 사용하고 결과 옆에 Wiby 링크를 제공한다. HTML 화면 추출이나 LLM 호출은 필수가 아니다.
2. API 응답은 불신 데이터로 취급한다. 텍스트 렌더링, HTTP(S) 링크 검증, 응답 크기·시간 제한을 적용하고 결과 클릭은 기존 격리된 웹 탭에서 연다. 외부 HTML·스크립트를 권한 있는 UI에 삽입하지 않는다.
3. 보이는 검색어를 전송하는 사용자 동작과 자동 후속 검색을 구분한다. 추가 페이지 요청·다른 제공사 전송·AI 전송은 사용자에게 드러나는 제품 정책과 해당 제공사 조건에 맞춘다.
4. 공유 비밀 키를 배포 EXE에 넣지 않는다. 보호된 중계가 필요한 제공사를 채택하면 중계 서비스의 무료 한도도 계산해야 한다. OS 암호화만으로 배포용 공용 키를 비밀로 만들 수 있다고 가정하지 않는다.
5. 429 등 제한 응답에서 재시도 폭주·다중 계정·IP 우회를 하지 않는다. 무료 한도 소진 시 동작을 제품에서 명확하게 표시한다.

이번 작업은 조사 문서와 공개 API의 소량 읽기 시험이다. 검색 기능 구현·제공사 변경·계정 생성·키 발급·운영자 메시지 발송·유료 서비스 신청·배포는 수행하지 않았다.
