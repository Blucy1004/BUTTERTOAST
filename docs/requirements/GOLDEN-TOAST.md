# PROJECT BUTTERTOAST — MASTER DEVELOPMENT DIRECTIVE
## Codename: Operation Golden Toast
### 목표: Chrome 수준의 안정성과 완성도를 갖춘 AI-Native Browser

당신은 지금부터 ButterToast 프로젝트의 수석 소프트웨어 엔지니어, Chromium 통합 전문가, AI 에이전트 아키텍트, UI/UX 엔지니어, QA 엔지니어 및 보안 검토자의 역할을 수행한다.

이번 작업은 단순한 기능 추가나 프로토타입 제작이 아니다.

**목표는 기존 ButterToast 코드베이스를 실제 사용자가 매일 사용할 수 있는 완성도 높은 AI 브라우저로 발전시키는 것이다.**

사용자는 장시간 자율 작업을 승인한다. 단, 외부 서비스에 대한 제출·결제·배포, 데이터 삭제 등 되돌리기 어려운 작업은 별도 승인을 받아야 한다.

가능한 범위에서 분석 → 설계 → 구현 → 테스트 → 오류 수정 → 재검증을 반복한다.

중간에 사소한 선택을 사용자에게 넘기지 말고, 코드와 실제 테스트 결과를 근거로 스스로 판단하라.

---

# PART 0. 최우선 개발 원칙

1. 기존 ButterToast 프로젝트를 처음부터 다시 작성하지 않는다.
2. 기존 Chromium 기반 브라우저 구조를 최대한 보존한다.
3. 현재 구현된 기능을 먼저 조사한다.
4. 미구현 기능을 구현된 것처럼 보고하지 않는다.
5. UI만 있는 가짜 기능을 실제 기능으로 연결한다.
6. 임시 목업, 더미 데이터, 성공을 가장하는 로직을 정식 기능으로 남기지 않는다.
7. 새 기능 추가보다 안정성·호환성·보안을 우선한다.
8. 무료 핵심 기능에 인위적인 속도 제한을 추가하지 않는다.
9. API 키와 인증 토큰을 안전하게 취급한다.
10. 각 단계마다 빌드와 자동 테스트를 수행한다.

**최종 목표는 AI 기능을 사용하지 않아도 충분히 좋은 브라우저이며, AI를 사용하면 기존 브라우저보다 훨씬 편리한 제품이다.**

# PART 3. AI 작업 환경

ButterToast의 핵심 차별점은 AI가 브라우저에서 직접 작업한다는 점이다.

기존에 구상한 UI 구조는 다음과 같다.

**왼쪽: 작업 및 편의 패널**

**중앙: 일반 브라우저 화면**

**오른쪽: AI 작업 및 조작 화면**

기존 디자인 명세가 있다면 이를 우선 적용한다.

## 3.1 AI 작업 패널

지원할 기능:

- 자연어 작업 요청
- 현재 탭 분석
- 특정 탭에서 작업 실행
- 여러 단계 작업 계획
- 실시간 작업 상태
- 작업 일시정지
- 작업 재개
- 작업 취소
- 실패 원인 표시
- 작업 완료 결과
- 실행 로그
- 사용자 승인 요청
- 사용자 개입

사용자가 AI에게 작업을 맡겼을 때 현재 무엇을 하고 있는지 알 수 있어야 한다.

## 3.2 드래그 기반 작업 위임

사용자가 웹페이지의 요소나 선택 영역을 AI 작업 패널로 드래그하여 작업을 요청할 수 있도록 한다.

가능한 예:

- 텍스트 선택 후 AI에게 전달
- 링크 드래그
- 이미지 드래그
- 현재 페이지 전달
- 탭 전달
- 파일 전달

지원하지 않는 드래그 데이터 형식은 명확하게 안내한다.

## 3.3 브라우저 조작

AI는 적절한 권한 아래 다음을 수행할 수 있어야 한다.

- 클릭
- 입력
- 스크롤
- 탭 이동
- 링크 탐색
- 폼 작성
- 화면 내용 분석
- 파일 선택
- 다운로드
- 웹페이지 정보 추출

가능하면 안정적인 DOM 기반 조작을 우선 사용한다.

필요한 경우 시각 기반 조작을 사용한다.

AI가 사용자의 입력과 충돌하지 않도록 제어권을 관리한다.

# PART 4. ToastIR — 핵심 실행 엔진

ToastIR은 ButterToast의 핵심 기술이다.

**ToastIR은 모든 사용자에게 무료로 제공한다.**

무료 플랜의 ToastIR 성능을 인위적으로 제한하거나 느리게 만들지 않는다.

기존 구현을 분석하고, 존재하는 구조를 최대한 활용한다.

## 4.1 목표

일반적인 화면 기반 조작과 구조화된 브라우저 조작을 상황에 맞게 선택하여 작업을 효율적으로 수행한다.

## 4.2 실행 방식

지원 가능한 실행 경로를 분석한다.

- DOM 기반 실행
- 브라우저 자동화 API
- 접근성 트리 기반 실행
- 시각 기반 실행
- 구조화된 명령 실행
- 배치 실행

각 방식의 장단점을 측정하고 적절한 실행 경로를 선택한다.

## 4.3 실행 안정성

- 명령 검증
- 실행 전 대상 확인
- 타임아웃
- 재시도
- 실패 감지
- 상태 복구
- 중복 실행 방지
- 취소 처리
- 작업별 격리

특히 결제, 파일 삭제, 외부 메시지 전송, 계정 변경처럼 위험한 동작은 명시적 사용자 승인을 요구한다.

## 4.4 성능 측정

다음 지표를 기록한다.

- 작업 완료 시간
- API 토큰 사용량
- 성공률
- 재시도 횟수
- 브라우저 CPU 사용량
- 메모리 사용량
- 사용자 개입 횟수

일반 실행과 ToastIR 실행을 동일한 작업 조건에서 비교한다.

실제 측정 결과 없이 성능 향상률을 주장하지 않는다.

# PART 5. AI 공급자 연결

ButterToast는 BYOK(Bring Your Own Key)를 기본 원칙으로 한다.

사용자는 자신의 AI API 키를 직접 연결한다.

우선 지원 대상:

- OpenAI
- Anthropic
- Google Gemini

가능하면 향후 공급자 추가가 쉬운 추상화 구조를 만든다.

## 5.1 API 키 보안

- 운영체제 보안 저장소 사용
- 평문 로그 출력 금지
- 프런트엔드에 불필요한 키 노출 금지
- 공급자별 키 분리
- 연결 테스트
- 키 삭제
- 키 교체
- 요청별 비용 추적

기본적으로 API 키를 Supabase에 저장하지 않는다.

## 5.2 ChatGPT 구독 연결

공식 Sign in with ChatGPT 연동을 위한 모듈을 설계한다.

중요한 조건:

**상용 연동 승인 여부가 확인되지 않은 상태에서 비공식 인증 우회를 구현하지 않는다.**

공식 SDK, OAuth, 문서화된 인증 방식만 사용한다.

- 공식 지원 범위 조사
- 인증 인터페이스 설계
- 토큰 로컬 보관
- 연결 해제
- 오류 처리
- 구독 사용량 제한 처리
- API 키 연결과 독립적인 공급자 구조

공식 승인이 필요한 기능은 승인 전까지 비활성 상태로 유지한다.

ChatGPT 구독 연결은 승인 후 무료 플랜에도 제공할 수 있도록 설계한다.

ChatGPT 로그인 기능을 사용하기 위해 ButterToast 유료 구독을 요구하지 않는다.

# PART 6. Supabase 인증 및 사용자 계정

Supabase는 사용자 인증과 필요한 최소한의 계정 데이터를 관리한다.

검토할 항목:

- 회원가입
- 로그인
- 로그아웃
- 이메일 인증
- 비밀번호 재설정
- 세션 유지
- 기기별 세션
- 계정 삭제
- 데이터 삭제
- Row Level Security
- 인증 오류 처리

브라우저의 민감한 데이터는 기본적으로 로컬에 보관한다.

사용자가 명시적으로 활성화하지 않은 클라우드 동기화는 수행하지 않는다.

계정 삭제와 데이터 삭제는 실제 저장소까지 반영되도록 설계한다.

# PART 7. ButterToast 요금제 기반

요금제 이름은 다음과 같다.

| 등급 | 이름 | 역할 |
|---|---|---|
| Free | Original | 무료 AI 브라우저 |
| Go | Margarine | 저렴한 편의기능 |
| Pro | 100% Milk | 고급 AI 작업 환경 |
| Ultra | Organic | 최고급 작업 환경 |

가격은 아직 확정하지 않는다.

결제 서비스와 실제 구독 청구는 사용자 승인 전까지 활성화하지 않는다.

## 7.1 무료 기능

다음 기능은 무료다.

- 일반 브라우징
- AI 웹페이지 조작
- 사용자 API 키 연결
- 기본 AI 작업 패널
- ToastIR 전체 핵심 실행 기능
- 기본 작업 기록
- 일반적인 작업 수행
- 공식 승인을 받은 ChatGPT 구독 연결

무료 버전에 인위적인 AI 속도 제한을 두지 않는다.

## 7.2 유료 기능 후보

- 병렬 AI 작업
- 고급 작업 대기열
- 워크플로 편집기
- 반복 작업 자동화
- 고급 작업 복구
- 작업 템플릿 관리
- 다중 모델 협업
- 확장된 작업 기록 관리
- 고급 생산성 도구

병렬 작업 수는 임의로 확정하지 말고 실제 CPU·메모리·안정성 테스트 결과를 기준으로 결정한다.

ChatGPT 구독 연결을 유료 기능의 필수 구매 조건으로 만들지 않는다.

## 7.3 권한 시스템

요금제별 기능 접근을 중앙에서 관리할 수 있도록 설계한다.

UI 표시만 숨기는 방식에 의존하지 않는다.

권한 검증은 신뢰 가능한 계층에서 수행한다.

결제 미연결 상태에서는 유료 기능을 실제 판매하거나 청구하지 않는다.

중요한 목표:

- 일관된 간격
- 명확한 시각적 계층
- 부드러운 애니메이션
- 빠른 상호작용
- 키보드 접근성
- 화면 크기 대응

- 라이트 모드

- 로딩 상태 디자인

UI가 실제 기능과 연결되어 있는지 검증한다.

작동하지 않는 버튼을 정상 기능처럼 표시하지 않는다.

## 9.1 AI 작업 시각화

AI가 브라우저를 조작하는 과정을 시각적으로 표현한다.

일반 모드에서는 실제 조작 상태를 보여준다.

ToastIR 고속 모드에서는 실행 상태를 효율적으로 시각화한다.

실제 수행하지 않은 마우스 조작이나 작업 성공을 연출하지 않는다.

시각화가 실제 실행 속도를 크게 저하시키지 않도록 한다.

# PART 13. 장시간 자율 개발 프로토콜

이번 작업은 장시간 실행을 전제로 한다.

작업을 작은 단계로 나누되, 각 단계가 끝났다는 이유만으로 전체 작업을 종료하지 않는다.

다음 순서로 진행한다.

1. 기존 코드 감사
2. 문제 목록 작성
3. 위험도와 사용자 영향 기준 우선순위 결정
4. 가장 중요한 문제 구현
5. 자동 테스트
6. 실제 실행 검증
7. 오류 수정
8. 회귀 테스트
9. 다음 문제로 이동

이 사이클을 반복한다.

단, 테스트 실패를 무시하거나 기능을 삭제해서 테스트를 통과시키지 않는다.

기존 구현과 충돌하는 변경이 필요하면 먼저 대안을 검토한다.

## 13.1 컨텍스트 관리

장시간 작업 중 컨텍스트가 압축되거나 세션이 바뀔 수 있다.

프로젝트 내부에 다음 문서를 유지한다.

`docs/DEVELOPMENT_STATE.md`

포함 내용:

- 현재 아키텍처
- 완료 작업
- 진행 중 작업
- 남은 작업
- 변경 파일
- 테스트 결과
- 발견된 결함
- 다음 작업 순서
- 중요한 설계 결정

필요한 경우 문서를 갱신하고 다음 세션에서 이어갈 수 있도록 한다.

## 13.2 작업 중단 조건

다음 상황에서는 임의로 진행하지 않는다.

- 사용자 데이터 삭제 필요
- 외부 서비스에 실제 결제 발생
- 공개 배포 필요
- 인증 정보 외부 전송 필요
- 보안 기능 약화 필요
- 프로젝트의 핵심 아키텍처를 파괴해야 하는 변경

이외의 일반적인 구현과 검증은 가능한 범위에서 자율적으로 진행한다.

# FINAL DIRECTIVE

ButterToast는 단순히 Chromium 위에 AI 채팅창을 붙인 제품이 아니다.

우리가 만들려는 것은 사용자가 브라우저를 직접 조작하는 시간을 줄이고, AI에게 작업을 위임할 수 있는 새로운 브라우저 경험이다.

핵심 철학은 다음과 같다.

**The toast is free. The toppings are optional.**

기본 브라우저, AI 작업, ToastIR은 무료다.

유료 플랜은 독립적인 고급 생산성 기능을 제공한다.

최우선 목표는 사용자가 실제로 매일 사용할 수 있는 안정적이고 빠르며 신뢰할 수 있는 브라우저를 만드는 것이다.

기존 코드베이스를 존중하고, 실제 구현을 검증하며, 문제를 발견하면 해결하라.

불필요한 확인 요청을 최소화하되, 권한이 필요한 작업은 반드시 사용자 승인을 받아라.
