# Operation Golden Toast — 0.4.0 개발 빌드

2026-11-09. 기준 소스는 `2a75990`의 0.3.0이며 기존 미커밋 변경 없이 시작했다. [원본 지시서](requirements/GOLDEN-TOAST.md), [시작 감사](audit/GOLDEN-TOAST-BASELINE.md), [현재 구현 표](IMPLEMENTATION-STATUS.md)를 함께 보관한다. 기존 Butter / Browser / Toast 디자인과 Electron 구조를 유지했다. 이 작업은 Chrome과 동등한 완성도나 모든 요구 완료를 주장하지 않는다.

## 실제 추가한 기능

### ToastIR · AI

- 열린 Shadow DOM의 요소/라벨 수집, 실제 Node 식별·변경 감지, composed ancestor의 비공개/숨김 영역 검사. 체크박스/라디오와 disabled optgroup 검사. 문서·버전·일회성 승인 경계 유지.
- 수집 한도: DOM 10,000노드, 요소 500개, 본문 12,000자, ShadowRoot 128개. 모델 입력은 그중 최대 100요소. 잘림 여부와 실제 수집 시간을 표시한다. 수집 응답은 5초를 넘으면 scope를 회수한다.
- 모델용 `toastir/1` 튜플 JSON과 변경분: 같은 source/origin/document, 정확한 baseVersion, ID 중복/누락 검증 후 원본과 동일하게 재구성되는 더 작은 프레임만 사용한다. 바이너리 BTIR를 모델에게 인코딩 문자열로 보내지 않는다.
- 원본과 변경분의 요청 이력은 명시적으로 승인한 연속 작업 동안 메모리에만 유지한다. 중지·제공사/모델 변경·문서 변경·공유 회수·이력 한도에서 리셋한다. 대화 저장본에는 페이지 원본/변경분을 넣지 않는다. 제공사에 보내는 전체 대화에는 앞선 기준 프레임도 포함되므로 변경분 크기 감소가 전체 요청 토큰의 같은 비율 감소를 뜻하지 않는다.
- READ/EXTRACT/VERIFY의 실제 관찰 결과를 다음 단계의 `untrusted_execution_result`로 전달한다. 사용자 지시로 승격하지 않는다. `dispatched`는 DOM 이벤트 전달이며 사이트 업무 성공의 증명이 아니다.
- 응답에 행동이 없다는 이유만으로 완료 처리하지 않는다. `action:null, done:true`일 때 모델의 완료 주장으로 표시하며, 아니면 확인 대기로 멈춘다. 서버 처리 완료를 독립적으로 증명하는 것은 아니다.
- 캡처/모델 응답 시간, 컨텍스트 바이트, 동작/실패/승인 수를 실제 이벤트에서 표시한다. API 사용량은 제공사 보고 토큰과 사용자가 입력한 단가에 따른 추정이다.
- 기존 대화당 30회·최소 1.5초 대기를 제거했다. 실제 제공사의 429 Retry-After, 사용자 예산, IPC 남용 방어, 작업별 안전 한도는 유지한다. 무료 핵심 기능을 요금제 때문에 늦추지 않는다.
- 텍스트/웹 링크를 AI 입력란으로 드래그하면 검토할 초안을 만든다. 전송은 사용자가 누른다. 파일·이미지 드래그는 미지원 안내를 한다. 탭 위임은 기존의 문서 바인딩 native 승인 경로를 사용한다.

### 브라우저

- 탭 세로 드래그 재정렬과 기존 가로 드래그 Toast 위임을 구분한다. 고정 탭 영역을 넘어 재정렬하지 않는다. 탭 한도는 64개이며 50개 측정은 [성능 기록](performance/GOLDEN-TOAST-0.4.md)에 있다. 무제한 안정성/최적 병렬 AI 개수의 근거는 아니다.
- 주소창의 로컬 북마크/기록 자동완성(최대 8개), Ctrl+Shift+R 강력 새로고침, F11, Ctrl+N 일반 탐색 새 창, 링크의 새 탭/창 메뉴.
- 추가 탐색 창은 기본 주소창·뒤로/앞으로·새로고침·다운로드와 같은 사람 쿠키 프로필을 사용한다. 현재 최대 8창, 별도 AI 패널·독립 탭 복원·모든 사이트 권한 UI는 미지원이다.
- 팝업은 먼저 차단하고 명시적인 native 확인으로 원래 창과 opener 연결 없는 새 탭만 연다. POST 팝업은 재생하지 않는다. 확인 대기 중 이동·충돌하면 동의를 버린다. 원래 팝업과의 `postMessage`에 의존하는 인증 사이트는 호환되지 않을 수 있다.
- 메모리 절약은 기본 끔. 15분 이상 비활성 페이지 중 고정·재생·권한·다운로드·입력·편집·미디어·프레임·Shadow DOM/커스텀 요소가 없는 페이지만 해제 후보로 삼는다. 페이지 입력/클릭 후에는 자동 해제하지 않는다. 사이트의 모든 메모리 상태를 저장하는 기능이 아니며 복원은 URL GET이다.
- Chrome 북마크 HTML, Takeout 방문 기록 JSON, ButterToast 설정 JSON 가져오기와 북마크 내보내기를 native 파일 선택/내용 개수 확인에 연결했다. 입력 HTML을 렌더링하거나 링크를 자동 요청하지 않는다. 비밀번호·쿠키·Chrome 암호화 키 가져오기는 구현하지 않았다.
- 다운로드 목록 최대 100개를 OS 암호화 저장한다. 렌더러에는 전체 저장 경로를 주지 않는다. 재실행 후 진행 중이던 항목은 `interrupted-after-restart`로 표시하며 자동 재요청/POST 재생하지 않는다. 완료 파일 자동 실행 없음.

### 계정 · 무료 기능 · 외부 연결

- 프로필은 기본적으로 이 기기의 OS 암호화 저장소에 둔다. 계정·기기별 명시적 동기화 선택 후에만 Supabase Auth 메타데이터를 읽고 쓴다. 끄면 이후 통신을 멈추지만 이미 서버에 저장된 프로필을 자동 삭제하지 않는다.
- 로그인 유지도 기본 끔. 선택하면 refresh token과 사용자 바인딩만 별도 암호화 파일에 저장하고 다음 시작에 서버에서 신원을 재검증한다. access token과 비밀번호는 저장하지 않는다. 로그아웃/만료가 저장 경쟁과 늦은 응답보다 우선하고, 새 세션 저장이 실패하면 이전 저장 세션도 제거한다. OS 보호 저장소가 없으면 로그인 유지 불가.
- 다른 기기 로그아웃은 현재 계정·세션에 묶인 native 확인 후 Supabase `scope=others`로 갱신 세션을 해제한다. 이미 발급된 JWT는 만료까지 유효할 수 있다. 기기별 목록/선택 해제는 미구현이다.
- 계정 삭제 서버 함수와 선택적 RLS migration을 준비했다. 소유자 서버 환경의 관리자 키, JWT 신원, 현재 비밀번호 재확인, 동일 사용자만 삭제하는 경로를 로컬 fixture로 검사했다. **Supabase에 배포하지 않았고 앱 계정 삭제 버튼도 활성화하지 않았다.** RLS는 실제 Postgres에서 실행 검증하지 않았다. [저장/삭제 범위](ACCOUNT-STORAGE-AND-DELETION.md).
- main의 중앙 기능 정책에 무료 핵심 브라우징/BYOK/ToastIR/기본 기록을 고정했다. 메타데이터의 plan/role로 권한을 올릴 수 없다. Original/Margarine/100% Milk/Organic은 표시와 설계 기반이며 실제 결제·유료 entitlement 발급은 없다.
- Support 설정은 실제 구현 상태와 고정 프로젝트 링크만 표시한다. 후원 계정·가격·금액·목표 진행률을 지어내지 않았다.
- 공식 문서에는 OSS/local 앱의 Sign in with ChatGPT 경로가 있다. 현재 저장소의 라이선스/상용 계획과 승인 상태가 미확정이므로 비활성 인터페이스·설계만 준비했다. 인증 우회나 Codex/브라우저 토큰 재사용 없음. [공식 연결 조사](CHATGPT-OFFICIAL-INTEGRATION.md).

## 발견·수정한 문제

| 문제 | 수정/검증 |

| 기존 일반 문서 수집은 열린 shadow 영역을 놓침 | bounded shadow traversal, shadow observer, composed privacy와 hit test를 실제 Electron에서 검사 |

| 단발 공유를 소비한 뒤 잘못 재사용할 수 있는 1차 구현 회귀 | frame 작성 전 공유 수명 검사, 단발/연속 공유 각각 재검증 |
| 행동 없는 모델 응답을 작업 완료로 표시 | 명시적 done, 불확실한 응답은 일시정지 |
| 새 탐색 UI가 기존 appearance 허용목록에서 누락 | 정확한 새 UI URL만 등록, 같은 URL 위조 창 방어 유지 |

## 검증 범위

Linux x64, Node 24.22.1, Electron 45.2.3 / Chromium 156.0.8078.80. sandbox, Site Isolation, TLS 검증을 유지했다. 임의 공격은 로컬 fixture에만 수행했다. 고의 renderer crash/TLS 거부 로그는 해당 테스트의 예상 결과다.

- `npm run test:security`: 단위 116개와 Electron 132그룹, audit/비밀정보 패턴 검사 통과. 마지막 저장 실패 정리/표시 보완 후 `npm test` 117개, 계정 8/프로필 9/Golden 7그룹을 재검증했다. Golden에는 native 탭 드래그 1그룹을 추가했고 중복 제외 현재 Electron 범위는 133그룹이다.
- Electron 영역: 브라우저 경계 16, ToastIR 29, 탭 생명주기 11, 확대 보안 12, 계정 8, AI 16, 관리 8, 워크스페이스 8, 0.2 확장 9, 프로필 9, Golden Toast 7.
- 의존성 audit: 알려진 npm advisory 0. Electron npm 최신 버전 조회와 45.2.3 일치. Chromium 전체 CVE 부재나 제로데이 안전성을 보증하지 않는다.
- 계정 저장/삭제 함수·RLS에 사용한 데이터는 fixture이다. Windows DPAPI, 실제 Supabase sync/삭제/다른 기기 로그아웃, 실제 모델 추론과 청구를 이번 결과로 주장하지 않는다.
- 실제 앱의 50탭 301.4초/454번 전환/22번 새로고침에서 충돌·응답 없음 0을 관찰했다. Google/GitHub/Wikipedia 등 6개 공개 첫 화면은 로드됐고 YouTube는 프록시 터널 오류로 미검증이다. 로그인 후 서비스 사용을 검증한 것은 아니다.
- 로컬 무음 VP9 클립의 실제 디코딩/재생과 fixture 파일의 multipart 폼 전송을 검사했다. 파일 선택은 테스트용 CDP, 제출은 웹 표준 requestSubmit이며 native 파일 선택창/포인터 제출은 이 headless 뷰에서 미검증이다.
- 정확한 측정 조건과 한계, 원본 JSON은 [성능 기록](performance/GOLDEN-TOAST-0.4.md)에 분리했다.

## 설치·업데이트와 남은 작업

0.4.0 Windows x64 포터블의 95개 앱 payload/PE/fuse/ASAR 해시와 SBOM 생성·검증을 완료했다. 이 폴더로 NSIS 개발 설치 프로그램을 생성한다. 패키지 payload/PE/fuse/ASAR 해시/SBOM 검증은 Linux에서 가능하지만 Windows 설치·덮어쓰기·제거·DPAPI 검증을 대신하지 않는다. 이전 릴리스는 그대로이며 이번 산출물은 외부 공개 배포하지 않는다. `READ-ME-FIRST.md`, `BUILD-VERIFICATION.json`, `LATEST-VALIDATION.md`를 배포 폴더에 넣는다.

우선순위가 높은 다음 작업:

1. Windows 11 실제 설치/업그레이드/제거·사용자 데이터 유지·로그인 유지/메일 콜백 검증, Authenticode와 운영 업데이트 feed 준비. 현재 자동 업데이트 비활성, 설치 실패 rollback 미구현.
2. 오너가 앱에 연결한 실제 모델로 다단계 작업 성공률/토큰/요금·복잡한 SPA/쇼핑/메일 사이트 호환성 측정. 외부 제출/구매는 사전 동의 범위 내에서만 검증.
3. 계정 삭제 함수의 서버 배포와 데이터 inventory/RLS 실검증, 사용자 데이터별 내보내기/삭제 정책, 계정 간 브라우저 데이터 격리 설계. 현재 로그인 계정은 프로필만 바꾸고 사람 쿠키·AI 키·브라우징 이력은 OS 프로필 공유.
4. iframe·닫힌 shadow·전체 AX 트리·시각 기반 실행 및 안전한 배치 경로는 미구현이다. DOM 경로가 불확실하면 사람 인계하며 보안 검사를 끄지 않는다. 이미지/파일 모델 첨부·AI 파일 선택/다운로드·사이트 간 자동 탐색도 별도 설계/동의가 필요하다.
5. 실제 자원 측정에 기반한 고급 작업 대기열/복구/워크플로 편집기·반복 실행·다중 모델 협업. 지금의 3슬롯을 유료 한도나 CPU 최적값으로 확정하지 않는다.
6. 공식 ChatGPT 연동 자격·승인/라이선스 확인 후 PKCE·토큰 보관·Responses/SSE·구독 사용량 처리 구현. 무료 기능 정책 유지. 후원 링크는 실제 프로젝트 소유 링크가 정해지면 연결하며 결제는 별도 승인 전까지 비활성.
7. 하루 단위 장기 사용, 실제 영상/DRM/코덱·사이트 파일 업로드·복잡한 로그인/팝업 호환성을 실제 OS에서 검증. 수분의 로컬 soak 결과를 장기 안정성이나 Chrome 동등성으로 확대하지 않는다.
