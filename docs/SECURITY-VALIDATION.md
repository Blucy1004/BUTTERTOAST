# 보안 검증 기록 — 2026-11-07

이 문서는 초기 셸 검증 기록이다. 최신 공식 공지·정적 검사·확대 공격 결과는 [확대 보안 검사](EXPANDED-SECURITY-REVIEW.md)에 있다. 최신 탭·자원·개인정보 기능과 전체 회귀 결과는 [추가 구현 기록](CHROMIUM-IMPROVEMENTS.md)에 있다. 이후 Guard v2 및 ToastIR/탭 경계 변경과 추가 결과는 [추가 검증 기록](TOASTIR-SECURITY-VALIDATION.md)에 있다.

범위: 현재 작업 트리의 개발용 ButterToast, Linux x64, Node 24.22.1, Electron 45.2.3. 실제 공격 대상으로 로컬 HTTP/HTTPS 서버와 별도로 만든 악성 렌더러만 사용했다. 다른 서비스나 사용자 계정을 공격하지 않았다. Windows 실행이나 출시 버전 검증을 의미하지 않는다.

## 결과

- `npm test`: 빌드 및 22개 단위/모듈 회귀 테스트 통과, 실패·스킵 0.
- `npm run test:electron`: 실제 Electron에서 13개 검증 그룹 완료, 종료 코드 0. Linux headless 및 소프트웨어 렌더링 사용, Chromium sandbox 유지.
- `npm run audit:deps`: 당시 npm 보고 취약점 0.
- `npm run scan:secrets`: 지원되는 자격 증명 패턴 미검출. 완전한 유출 분석이 아니다.
- `npm run sbom`: `artifacts/sbom.cdx.json` 생성.

초기 실행은 도구 내부의 제한된 사용자 namespace에서 실패했다. 승인된 외부 명령 실행 경로에서는 샌드박스를 유지한 Electron이 정상 시작해 E2E를 실행했다. 보안 해제 플래그나 TLS 우회는 사용하지 않았다. D-Bus 부재 로그, 의도한 렌더러 강제 종료 로그와 인증서 거부 로그는 발생했다.

| 시도 | 관찰 결과 |
| --- | --- |

| 악성 팝업·로컬 파일 링크 | 창 추가와 파일 탐색 차단 |

| UI 경로·호스트 변조와 외부 네트워크 접근 | 허용된 정적 파일 외 요청 거부 |

OS 저장소가 제공되지 않아 실제 암호화/복호화 왕복은 Linux에서 **미실행**이다. 단위 테스트의 가짜 cipher는 파일 저장 경계와 오류 처리를 검증할 뿐 암호화의 증거가 아니다. Windows CI는 DPAPI 사용 가능 및 실제 왕복을 요구하도록 작성했지만 아직 실행하지 않았다.

## 검토 중 보완한 부분

이전 셸의 느슨한 IPC 구조를 엄격한 스키마와 빈도 제한으로 바꾸고, UI의 file 기반 로딩을 파일 허용 목록이 있는 전용 프로토콜로 교체했다. 이는 공격 표면 축소이며 이전 버전에서 OS 권한 탈취가 입증됐다는 뜻은 아니다.

구현 과정에서 완료 콜백의 실행 ID가 없으면 늦은 완료가 새 실행 잠금을 풀 수 있는 경합을 확인했다. 실행별 lease 일치 시에만 잠금을 해제하도록 수정하고 회귀 테스트를 추가했다. 비동기 키 저장과 삭제 순서가 바뀌어 키가 다시 저장되는 경합은 저장소 작업 직렬화로 막고 지연 암호화 테스트로 검증했다.

## 모듈 테스트의 한계

모델의 추가 지시·코드 필드, 다른 탭/사이트, 오래된 버전, 민감/제거/비활성 대상, 승인 없는 결제 가능 클릭, 승인 변조·만료·재사용, 중복 실행, 사용자 중단과 작업 수 제한을 검사했다. 실제 DOM 실행기와 연결되지 않았으므로 실제 프롬프트 인젝션 성공률, DOM 변경 도중 클릭의 원자성 또는 브라우저에서의 AI 중단 효과는 아직 검증되지 않았다.

업데이트 테스트는 매 실행 생성한 테스트용 Ed25519 키로 서명·manifest·파일 변조, 잘못된 게시자, rollback·만료·호스트 변경을 검사한다. 실제 업데이트 배포와 Windows Authenticode 검증은 미구현이다. 자동 업데이트가 안전하게 운영된다는 주장을 하지 않는다.

## Windows 테스트 패키징 추가 검증

Electron 45.2.3의 Windows x64 바이너리를 사용해 폴더형 테스트 빌드를 만들었다. 앱 payload 16개 파일이 ASAR에 기대한 바이트 그대로 포함됐는지 검사했고, Windows PE/x64 형식·7개 fuse·exe 리소스의 ASAR 헤더 해시 일치를 확인했다. 이 ASAR를 Linux Electron에서 실행한 동일한 13개 E2E 검증 그룹도 통과했다. Windows exe 직접 실행과 Windows에서의 무결성 차단 동작은 미검증이다.

패키징 도구에 추가된 glob/minimatch 의존성에서 npm이 중간 등급 취약점을 보고했다. @electron/asar 범위의 overrides로 glob 14.0.4와 minimatch 11.0.5를 고정했다. 다시 수행한 audit은 0건이며, 이 조합으로 실제 패키징 및 파일 일치 검증을 통과했다. 향후 upstream이 수정 버전을 채택하면 overrides를 재평가한다.

실행 파일은 코드 서명되지 않았다. ASAR 해시 검증을 코드 서명이나 게시자 진위 보증으로 취급하면 안 된다.
