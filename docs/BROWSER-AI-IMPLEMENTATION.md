# 브라우저·AI 확장 구현과 검증 — 2026-11-08

## 사용법

- 위쪽 ☆ 또는 Ctrl+D로 현재 탭을 북마크한다. `관리`에서 북마크·방문 기록·다운로드·설정·사이트 권한·감사 이력을 연다. Ctrl+H는 기록, Ctrl+J는 다운로드다.
- 관리 → 설정에서 검색엔진과 Google 검색 테마를 선택한다. 기록/탭 복원 설정과 사이트 데이터 삭제, OS 기본 브라우저 선택을 제공한다.
- 다운로드는 매번 출처/파일명과 저장 위치를 네이티브 창에서 확인한다. 완료 파일을 자동으로 실행하지 않는다.
- `AI 1`에서 연결하고 `다음 AI`로 독립된 AI 1·2·3을 전환한다. 각 모델·키·대화·작업 창을 따로 관리한다.
- 현재 탭 읽기는 읽기 전용, 현재 탭 제어 공유는 동의 후 동작 제안 가능이다. 직접 키/마우스를 입력하면 공유를 회수한다. 동작별 네이티브 승인은 항상 별개다.
- 여러 단계 작업은 별도 AI 작업 창에서 공유 승인 후 최대 10단계로 진행한다. 사이트/문서 변화와 불확실한 결과는 멈추고 확인 후 계속한다.
- 계정 창에 비밀번호 찾기·변경·재인증 코드 입력을 추가했다. 실제 메일 복구/Windows 콜백은 별도 검증 대상이다.

## 새 공격·회귀 범위

위조된 관리/AI 창과 추가 권한 필드, 자격 증명/다운그레이드 다운로드 URL, 파일 경로·예약 이름·양방향 제어 문자, 승인 취소 시 파일 미생성, 완료 파일 바이트 일치, Google 유사 도메인 테마 배제, HTTPS 권한 승인/철회, 이름의 HTML 주입을 검사했다.

AI 입력은 정확한 승인 없이 실행하지 못하고, 승인 뒤 password로 바뀐 필드는 거부한다. SELECT·WAIT 중단·HANDOFF·BTIR 왕복/변경분·압축/스키마/순환 부모 거부, origin 변경 시 작업 중단, 사람 제어 동의와 실제 키 입력에 따른 회수, 숨겨진 패널 IPC와 AI별 대화/네트워크 분리를 검사했다. 웹 이벤트의 실제 서버 효과나 거래 금액을 증명한 것은 아니다.

계정 복구는 PKCE/예상 이메일 바인딩과 세션 없는 비밀번호 변경 거부, 성공 뒤 로그아웃을 로컬 fixture로 검사했다. 업데이트는 서명 검증 전에 바이너리를 요청하지 않고 리디렉션·변조·다른 origin을 거부한다. 실제 게시자 키·업데이트 서버는 없다.

## 로컬 성능 측정

200개 section의 고정 fixture, 1050×720 창, 1회 워밍업 후 5회 측정의 중앙값이다. Node/Chromium 샌드박스를 유지했다. 초기 headless 캡처가 빈/미생성 화면을 반환해 실제 크기를 확인하는 검사를 추가했으며 아래 수치는 정상 크기의 캡처 재측정 결과다.

| 표현 | 크기 | 수집 중앙값 |
| --- | ---: | ---: |
| 전체 DOM HTML | 125,726 bytes | 1.86 ms |
| ToastIR JSON, 401 요소 | 72,411 bytes | 8.85 ms |
| ToastIR 바이너리 | 2,973 bytes | 위 캡처 후 별도 인코딩 |
| 화면 PNG | 80,928 bytes | 31.16 ms |

IR은 작은 표현을 만들지만 이 fixture에서 DOM 문자열 수집보다 계산 비용이 컸다. DOM/IR은 문서, PNG는 화면 영역을 담으므로 동등한 정보량이 아니다. 실제 모델 토큰·호출 횟수·비용·작업 성공률을 측정하지 않았다. 3배 속도·50% 토큰·70% 호출 절감·95% 성공률 목표를 달성했다고 주장하지 않는다. 원본은 `artifacts/performance-local.json`이다.

실제 모델/로컬 모델 추론, 일반 사용자 SMTP, 실제 Windows DPAPI·메일 콜백·기본 브라우저·설치/제거, Authenticode와 운영 업데이트, 실제 모델 성능/복잡한 사이트 공격 검증이 남아 있다. 전체 AX·iframe·shadow DOM과 PQ TLS 실제 협상 표시는 현재 구현 범위 밖이다. 최종 UI는 오너 명세를 기다린다. [전체 현황](IMPLEMENTATION-STATUS.md)과 [보안 경계](../SECURITY.md)를 참조한다.
