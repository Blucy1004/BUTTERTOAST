# 탭 안정성·자원 사용·개인정보 보호 — 2026-11-07

Chromium 엔진을 포크하거나 취약점이 모두 해결됐다는 의미가 아니다. Electron 브라우저 계층에서 구현한 기능과 실제 검증 범위를 기록한다. 최종 디자인은 오너가 결정하며 현재 버튼은 기능 검증용이다.

## 구현

| 영역 | 동작 |
| --- | --- |
| 탭 관리 | 최대 30개, 순서 이동, 최근 닫은 10개 탭의 URL 다시 열기. 닫은 목록은 메모리에만 유지 |
| 페이지 멈춤 | 로딩 30초 초과 표시·중지, Chromium 응답 없음/충돌 표시, 현재 탭 재시작. 자동 반복 재시작 없음 |
| 응답 확인 | 기본 응답 없음 이벤트의 누락을 보완. 로드가 끝난 활성 탭만 5초 간격, 응답 기한 10초, WebContents당 미완료 확인 1개. 고정된 `void 0` 코드를 별도 isolated world에서 실행하며 페이지 데이터나 모델 문자열을 읽지 않음 |
| 메모리 해제 | 사용자가 현재 탭의 WebContents를 닫고 URL만 유지. 선택하면 새 콘텐츠 생성. 자동으로 작성 중인 탭을 폐기하지 않음 |
| 백그라운드 | Chromium backgroundThrottling을 명시적으로 유지. 세션 복원 시 모든 탭을 대기 상태로 생성하고 선택한 탭만 로드 |
| 재실행 복원 | URL·순서·활성 위치만 OS 보호 저장소 어댑터로 암호화해 `userData/tabs.enc`에 저장. 평문 대체 없음. 저장소 불가·오류는 UI에 표시 |
| 추적 요청 | `google-analytics.com`, `doubleclick.net`, `googlesyndication.com`, `connect.facebook.net` 및 하위 호스트로 가는 타사 요청 차단. 호스트 경계를 검사하며 직접 탐색과 해당 호스트의 자체 리소스는 허용 |
| 개인정보 헤더 | 사람 탭과 AI 작업 세션에 `Sec-GPC: 1`, `DNT: 1`. 다른 origin으로 보내는 Referer는 origin까지 축소하고 HTTPS→HTTP이면 제거. 동일 origin의 정상 Referer, Origin, 인증·쿠키 헤더는 유지 |
| 사이트 예외 | 현재 사이트의 정확한 origin(스킴·호스트·포트)에 한해 추적 차단 해제. 재실행 시 초기화. 예외에도 개인정보 헤더는 유지 |

탭 재시작·메모리 해제·닫은 탭 다시 열기는 입력 내용과 페이지 내 상태를 복원하지 않는다. 복원은 URL을 GET으로 다시 열며 POST 본문이나 브라우저 탐색 이력을 재전송하지 않는다. URL 자체에도 토큰이 있을 수 있으므로 암호화하며, HTTPS/HTTP 외 스킴·URL 내 자격 증명·제어문자·과도한 크기·알 수 없는 저장 필드를 거부한다. 종료 시 진행 중인 저장을 기다리고 임시 파일과 rename으로 저장 중 손상을 줄인다. 강제 전원 종료 직전 변경까지 보장하지 않는다.

## 단축키

Windows/Linux 기준이다. 웹페이지에 포커스가 있어도 메인 프로세스에서 처리한다.

| 키 | 기능 |
| --- | --- |
| Ctrl+L / Ctrl+T / Ctrl+W | 주소창 / 새 탭 / 현재 탭 닫기 |
| Ctrl+Shift+T | 최근 닫은 탭 다시 열기 |
| Ctrl+Tab / Ctrl+Shift+Tab | 다음 / 이전 탭 |
| Ctrl+1…8 / Ctrl+9 | 해당 순서 / 마지막 탭 |
| Ctrl+Shift+PageUp / PageDown | 현재 탭 왼쪽 / 오른쪽 이동 |
| Ctrl+R 또는 F5 / Esc | 새로고침 / 로딩 중지 |

UI는 `tabs.js`, `toolbar.js`로 분리되어 있고 생명주기는 `src/browser/tabs.ts`가 담당한다. 새 명령에도 기존 UI 발신자·최상위 프레임 검증, 엄격한 스키마와 빈도 제한을 적용한다. 사이트 예외의 origin은 메인이 탭 상태에서 정하며 IPC 인자로 받지 않는다. UI 세션의 정적 파일·외부 통신 제한은 별도로 유지한다. AI 작업의 세션과 Guard 권한을 사람 탭 저장 데이터에 포함하지 않는다.

## 로컬 검증

Linux x64, Node 24.22.1, Electron 45.2.3, Chromium sandbox 및 TLS 검증을 유지했다. 로컬 fixture만 사용했다.

- `npm test`: 31개 모듈 검사 통과. 저장 스키마·동시 저장·오류·평문 대체 금지, 추적 호스트 경계·Referrer 정책, 새 IPC 변조와 기존 Guard 검사 포함.
- `npm run test:electron`: 16개 실제 앱 검증 그룹 통과. 기존 13개 공격 회귀에 페이지 포커스 단축키, 임시 UI 해제/복원/재시작, 사이트 예외 origin 변조 거부 추가.
- `npm run test:toastir`: 요소 바꿔치기·승인 우회·탭/AI 세션 정보 경계 등 16개 그룹 통과.
- `npm run test:browser`: 11개 그룹 통과. 무한 루프 렌더러의 실제 응답 지연·복구, 충돌 후 다른 사이트 탭 응답, 8개 탭의 콘텐츠 전부 해제 및 선택한 1개만 생성, 30개 상한, 지연 복원, 긴 페이지 URL의 실제 주소 표시와 저장 제외, 순서/최근 닫기, 로딩 중지, POST 재전송 금지, 서버에서 추적 요청 차단 및 헤더 확인.

처음 무한 루프 실험에서는 기본 unresponsive 이벤트가 오지 않았다. 이에 활성 탭 응답 확인을 추가한 뒤 동일한 실제 루프의 감지·복구를 확인했다. 메모리 해제 검사는 WebContents 파괴 완료까지 기다린 결과이며 RSS 감소율이나 배터리 시간 측정이 아니다. UI 모듈과 실제 앱 연결도 별도 시험했다.

## 한계와 후속 작업

- 수동 해제·지연 복원·기본 백그라운드 제한을 구현했다. CPU/배터리 절감률, 장기 실행 및 대규모 사이트 호환성은 미측정이다. 서비스 워커·공유 프로세스·캐시는 남을 수 있어 탭 수에 비례하는 RSS 절감을 보장하지 않는다.
- 다른 사이트 탭의 생존을 확인했다. Chromium이 같은 사이트의 렌더러를 공유하는 경우, GPU·메인 프로세스 충돌, OS 전체 메모리 고갈을 격리한다는 보장은 없다. 응답 확인은 현재 활성 탭에 한정되고 로딩 중 멈춤은 로딩 지연 안내로 처리한다. 심한 CPU 부하에서도 응답 없음 표시가 날 수 있어 자동 종료하지 않는다.
- 추적 호스트 목록은 작은 시작 목록이다. 완전한 광고 차단·지문 방지·CNAME 우회 탐지·쿠키 분할은 구현하지 않았다. WebContents에 연결되지 않은 워커/세션 요청은 타사 판단을 하지 않는다. GPC/DNT 준수는 서버에 달려 있다. 예외는 열린 탭들 중 같은 origin 전체에 적용된다.
- URL 복원 저장소는 API 키와 같은 OS 어댑터를 쓴다. 이번 Linux 환경에서는 보호 저장소를 사용할 수 없어 실제 OS 암호화 왕복은 미실행이다. 모듈 테스트용 cipher는 OS 보호의 증거가 아니다. 세션 복원은 저장 모듈 시험과 실제 탭 관리자의 지연 복원 시험으로 나눠 확인했다. Windows DPAPI·실제 프로세스 재실행 복원 검증은 별도로 필요하다.
- 사용자 세션의 정상적인 쿠키·localStorage 공유와 기존 Chromium 디스크 저장은 유지한다. `tabs.enc`의 보호를 브라우저 프로필 전체 암호화로 해석하면 안 된다.
- 이번 변경은 Linux 실행으로 검증했다. Windows용 CI에 회귀 명령을 추가했지만 그 실행 결과나 새 Windows 실행 파일을 검증했다는 의미는 아니다.
