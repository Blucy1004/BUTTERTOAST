## 0. 최상위 지시

당신은 ButterToast 프로젝트의 수석 아키텍트이자 개발 책임자다.

목표는 기획서나 프로토타입만 만드는 것이 아니라 **실제로 실행하고 사용할 수 있는 Chromium 기반 AI 협업 웹브라우저를 완성하는 것**이다.

전체 프로젝트를 직접 설계, 구현, 빌드, 테스트, 디버깅하라.

사용자가 이미 확정한 제품 요구사항을 임의로 축소하지 마라.

작업이 길어지면 구현을 여러 단계로 나누되, 단계마다 실제 코드를 작성하고 검증하며 다음 단계로 진행하라. 계획만 작성하고 종료하지 마라.

실패한 테스트를 성공했다고 보고하거나, 구현하지 않은 기능을 완료했다고 표시하지 마라.

기존 프로젝트가 존재한다면 먼저 검사하고 기존 코드를 보존하면서 작업하라.

## 1. 제품 정체성

ButterToast는 사람과 AI가 같은 브라우저 환경에서 협업하는 데스크톱 브라우저다.

기존 AI 브라우저와의 차별점:

- 사람과 AI의 독립적인 작업 공간
- 필요할 때 같은 페이지를 공동 조작
- 사람과 AI 사이의 제어권 인계
- AI가 직접 DOM이나 화면을 조작하지 않는 구조
- 웹페이지를 AI 전용 중간 표현으로 변환하는 ToastIR
- 브라우저 실행기가 실제 조작을 담당
- 다양한 AI 제공사와 사용자 API 키 지원
- 토큰 사용량 및 비용 가시화
- 강력한 보안 격리와 권한 통제
- 모델 호출 횟수와 불필요한 화면 분석 최소화

## 2. 기술 스택 선정

Chromium을 기반으로 구현하라.

Electron, CEF, Chromium 직접 통합 방식을 비교한 뒤 보안, 유지보수, 업데이트 속도, 브라우저 기능, 개발 비용을 고려해 적합한 방식을 선정하라.

선정 근거를 `docs/ARCHITECTURE.md`에 기록하라.

권장 방향:

- Chromium 기반 렌더링
- TypeScript 기반 UI 및 애플리케이션 계층
- 성능과 보안에 민감한 모듈은 Rust 검토
- 프로세스 간 통신에 명시적 스키마 적용
- 브라우저 콘텐츠와 특권 프로세스 격리
- 모델 제공사별 독립 Adapter

보안 기능을 비활성화하는 방식으로 성능을 개선하지 마라.

## 4. ToastIR — AI 전용 중간 표현

가장 중요한 핵심 기술이다.

AI 모델이 HTML, CSS, JavaScript 및 전체 화면을 매번 직접 해석하지 않도록 웹페이지를 기계 최적화된 중간 표현으로 변환하라.

구조:

1. Chromium에서 DOM 및 접근성 정보 수집
2. 의미 있는 요소와 관계 추출
3. 불필요한 정보 제거
4. 요소별 식별자 부여
5. 페이지 상태 버전 관리
6. 바이너리 ToastIR 생성
7. 변경 사항의 증분 갱신
8. Model Adapter를 통한 모델별 효율적인 표현 제공

ToastIR에는 다음 정보를 포함하라.

- 페이지 식별자
- 상태 버전
- 요소 ID
- 요소 역할
- 접근성 이름
- 텍스트 및 필요한 속성
- 요소 계층 관계
- 가시성
- 활성화 상태
- 허용 가능한 동작
- 상태 변경 정보

내부 표현은 바이너리 기반으로 설계하되, 모델에 비효율적인 바이너리 인코딩을 무조건 전달하지 마라.

모델별 토큰 비용과 해석 정확도를 측정하여 전송 표현을 최적화하라.

ToastIR은 실제 DOM과 요소 ID의 대응 관계를 관리해야 한다.

오래되거나 모호한 요소 참조는 무효화하라.

## 5. ToastCore — 초고속 실행 엔진

AI 모델은 행동을 결정하고, ToastCore가 실행한다.

모델이 직접 브라우저 내부 객체나 임의의 JavaScript 실행 권한을 갖지 않도록 하라.

지원할 동작:

- CLICK
- FILL
- SELECT
- SCROLL
- NAVIGATE
- WAIT
- READ
- EXTRACT
- VERIFY
- HANDOFF

실행 절차:

1. 모델의 구조화된 행동 명령 수신
2. 명령 스키마 검증
3. 권한 검사
4. 페이지 버전 확인
5. 대상 요소 재검증
6. Chromium에서 동작 실행
7. 결과 확인
8. 변경된 상태만 ToastIR에 반영
9. 필요 시 모델 재호출

안전한 작업은 짧은 배치로 실행할 수 있도록 하라.

예상과 다른 상태가 발생하면 실행을 중단하고 모델에 재판단을 요청하라.

중복 클릭, 중복 제출, 오래된 요소 참조, 무한 재시도를 방지하라.

## 6. ToastGuard — 최고 수준의 현실적인 보안

ButterToast는 보안을 최우선으로 설계한다.

### 브라우저 보안

- Chromium 샌드박스 유지
- Site Isolation 유지
- HTTPS 우선
- TLS 인증서 검증
- 안전한 콘텐츠 보안 경계
- 웹페이지와 특권 프로세스 분리
- 최소 권한 IPC
- 불필요한 Node.js 및 네이티브 API 노출 금지
- 웹페이지의 임의 코드가 OS 권한을 얻지 못하도록 설계
- 안전한 다운로드 및 파일 접근 정책
- 최신 보안 패치 적용 가능 구조

### AI 보안

- AI 모델을 신뢰하지 않는 의사결정 구성 요소로 취급
- ToastGuard가 모든 실제 실행 권한을 결정
- 사이트별 권한 분리
- 읽기·쓰기·전송·삭제·결제 권한 분리
- 외부 웹페이지의 지시문을 상위 명령으로 승격하지 않음
- 프롬프트 인젝션 방어
- 다른 탭과 다른 사이트의 정보 접근 제한
- 사용자 즉시 중단 기능
- 위험 작업의 명시적 승인
- AI 작업 이력 기록
- 민감정보 기본 비공개

### API 키 보안

- Windows DPAPI 등 OS 보호 저장소 사용
- API 키 평문 저장 금지
- 로그와 오류 보고에서 비밀정보 제거
- 모델 호출 시 필요한 구성 요소만 키에 접근
- 웹페이지와 렌더러에 API 키 노출 금지
- 사용자별·제공사별 키 관리
- 키 삭제 및 교체 기능

### 양자내성 보안

가능한 범위에서 검증된 하이브리드 양자내성 TLS 키 교환을 활용하라.

X25519와 ML-KEM 계열 기술을 검토하라.

Chromium과 서버의 실제 지원 여부를 확인하고 호환성을 유지하라.

암호 알고리즘이나 TLS 구현을 직접 제작하지 마라.

양자내성 연결 여부를 확인할 수 있다면 실제 협상 결과를 기반으로 표시하라.

### 공급망 보안

- 의존성 취약점 검사
- 소프트웨어 구성요소 명세(SBOM)
- 코드 서명 및 업데이트 검증
- 안전한 자동 업데이트
- CI 보안 검사
- 비밀정보 유출 검사
- 보안 회귀 테스트

보안 기능을 단순히 추가했다고 안전하다고 선언하지 마라. 테스트 가능한 보안 요구사항을 작성하고 검증하라.

## 10. 성능 최적화

ButterToast의 핵심 경쟁력은 AI 웹 작업 속도다.

다음 방식을 구현하고 비교하라.

- 스크린샷 기반 자동화
- 전체 DOM·접근성 구조 기반 자동화
- ToastIR 기반 자동화

측정 항목:

- 전체 작업 완료 시간
- 성공률
- 모델 호출 횟수
- 입력·출력 토큰
- ToastIR 변환 시간
- DOM 변경 처리 시간
- 브라우저 조작 지연
- CPU 및 메모리 사용량
- 작업별 API 비용

초기 목표:

- 반복 작업 속도 3배 향상
- 모델 입력 토큰 50% 절감
- 불필요한 모델 호출 70% 감소
- 대표 작업 성공률 95% 이상

위 수치는 목표이지 보장된 성능이 아니다.

측정 결과가 목표에 미달하면 원인을 분석하고 개선하라.

보안 기능을 비활성화하여 얻은 성능 개선은 인정하지 않는다.

- 승인 없는 결제·삭제·전송

- 모델 API 장애

## 12. 개발 진행 방식

전체 구현을 목표로 다음 순서로 진행하라.

**Phase 1 — 기반 구축**
- 프로젝트 구조
- 기술 스택 확정
- Chromium 브라우저 셸
- 보안 기본 설정
- 빌드 및 테스트 환경

**Phase 2 — ToastIR**
- 페이지 구조 수집
- 바이너리 IR
- 요소 매핑
- 증분 갱신
- 모델 전달 Adapter
